# Innovation — bounded framing instead of a bounded read

## User Input and seed
_branch.md plus four Decomposition questions. Failure seed: canonical line buffering
hid the input that the application intended to bound. Value: usable login with safe
refusal and small private responsibility, before another implementation plan.

Inherited mode: Standard default with a production-task piece list. Alternative:
Contrarian-rethink would focus on removing terminal input or changing refusal timing.
Use Standard default with all seven mechanisms and those explicit inversions; no
coverage reduction. All four pieces are meta-decisions (support/frame, value criteria,
retirement intervention, qualification criteria). Each receives generic/focused/
contrarian variants BEFORE testing. This is contract exploration, not product code.

## Generation — full candidate field

### Q1 — observation and supported context
G1 Generic: use a mature terminal input backend, with a private outer resource owner
and adapter for cancellation. Lens shifting: broader editing requirements justify
outsourcing the frontend, but ownership still needs qualification.
F1 Focused: replace canonical delivery with a small private byte-observable input
mode, preserving only declared controls. Combination: existing terminal owner plus
stream parsing; constraint ADD: finite UTF-8 input and deliberately basic editing.
C1 Contrarian: keep canonical editing and impose a whole-prompt deadline. Inversion
of REPAIR-mode-selection to ADD-TEST/ADD-CONTENT timing contract: failure becomes safe
timeout rather than immediate length refusal. At system level, bound waiting instead
of requiring byte observation. Existence-axis: zero new editor. Identity-axis: a
bounded interaction need not identify which input condition caused its timeout.

### Q2 — framing and invalid values
G2 Generic: a complete Unicode editor with cursor/history/paste modes and configurable
bindings. Extrapolation: useful if tgdata becomes an operator UI rather than one login.
F2 Focused: at most128 retained UTF-8 bytes, strict final decoding, basic configured
erase/clear controls before overflow. On excess, latch invalid state and discard
without retaining payload until newline/EOF/stop. Domain transfer: bounded protocol
parsers discard an invalid record rather than treating its suffix as a new record;
industrial reject handling keeps the reject path separate from accepted output.
C2 Contrarian: remove editing entirely; accept paste-or-restart only. Inversion:
REPAIR framing without building editing; existence-axis zero edit commands, identity-
axis inputs as immutable submissions rather than editable lines. Constraint REMOVE:
drop familiarity to reduce code, without removing the no-truncation requirement.

### Q3 — completion and resource retirement
G3 Generic: explicit producer framing/acknowledgment, including bracketed paste or a
helper process protocol, to know when a producer has finished. Absence redesign:
terminal byte streams carry no universal “producer is finished forever” receipt.
F3 Focused: retain one owner across valid/invalid input, consume the invalid line
through its delimiter (or explicit stop/EOF), discard queued typeahead, restore and
read back exact modes before release. Treat late FUTURE writes as outside the owned
interaction rather than promise to erase them. Combination + domain transfer.
C3 Contrarian: return as soon as byte129 is observed and flush/restore immediately.
Invert REPAIR retirement to REMOVE invalid-line drain; scope is only buffered bytes.
System-level inversion: successful refusal is immediate output, not settled input.
Patch-level absence: no invalid-remainder state existed. Already-present counterpart:
the terminal owner/flush/cleanup boundaries exist; this is not a new global lifecycle.

### Q4 — evidence and replacement plan
G4 Generic: a cross-platform terminal conformance framework qualifying every emulator,
encoding, keyboard map and signal family. Extrapolation from repeated review failures.
F4 Focused: native fragmentation/partial-write/oversize/controls/cancellation experiment,
then replace the input premise in desc and plan; keep a full combined candidate
prebuild mandatory before product changes. Absence: independent framing histories;
already present: actual SDK/PTY/publication regression suite and artifact manifests.
C4 Contrarian: classify huge pastes as unsupported misuse, retain the prior candidate
and its passing cases. Invert REPAIR to DO-NOTHING/REFRAME-AS-BUG-at-test: remove the
failed test instead of altering input behavior. System-level inversion challenges
whether robustness is actually part of this command's requested value.

## Seven-mechanism trace
Lens shifting:G1/C1. Combination:F1/F3. Inversion:C1/C2/C3/C4 (all four pieces;
intervention-shape where each commits REPAIR). Constraint manipulation:ADD F1/F2,
REMOVE C2; removing all size bounds also considered and rejected below. Absence
recognition:patch-level missing invalid-line state (F2), redesign-level missing
producer completion contract (G3), already-present owner/evidence (F3/F4). Domain
transfer:F2/F3 use computing-native record parsing and distinct physical reject-
handling analogy; neither analogy is treated as OS evidence. Extrapolation:G2/G4.

## Inherited Frame Audit (before testing)
Central assumptions: terminal command remains needed, private ownership stays local,
accepted input is finite, native tests should precede implementation. Explicit
challenges:G1 (backend ownership extent), C2 (interaction removal), G3 (producer
protocol instead of implicit input), C4 (robustness/evidence criterion), C1 (timing
instead of observed length). Remove size bound candidate would accept any length;
its implications are tested below. No shared assumption is deemed validated merely
because multiple mechanisms inherit it. Four pieces invert their shape/criteria;
no override needed; no audit rerun forced.

## Five-test cycle
N=novelty relative to failed plan; S=strongest objection/scrutiny; F=fertility;
A=actionability; M=mechanism independence. These are conceptual survival tests;
new mechanisms remain subject to native adversarial qualification in Critique.

### G1 — mature terminal backend
N:changes backend ownership surface. S:maturity does not prove this exact resource/
signal contract; adds dependency and adapter. F:rich UI consumer could benefit.
A:possible, but actual backend still needs independent qualification. M:human editing
needs support it, while native evidence still demands explicit ownership.
Disposition:DEFERRED; revive if basic private input cannot satisfy a required context
or an actual second frontend requires rich editing. No unexamined library is approved.

### F1 — private byte observation
N:replaces hidden whole-line dependency. S:noncanonical mode alone does not frame
input or prevent transformations; pair with explicit controls and F2/F3. F:small
input boundary reusable across existing prompts. A:native read/termios mechanisms
available. M:native partial-write/delivery observation plus separation of input value
and resource lifetime independently support it. SURVIVE direction, native proof due.

### C1 — canonical deadline
N:changes timing contract. S:avoids endless wait but cannot identify overflow, and
adds a deadline to ordinary human phone/code/password entry. F:optional interactive
timeout might be useful independently. A:implementable with existing select owner.
M:bounded waiting reasoning supports it, but user value has no requested deadline.
Disposition:DEFERRED, revive on explicit bounded-prompt timing requirement or failure
of byte observation under a required context. Not rejected merely for being smaller.

### G2 — complete Unicode editor
N:substantial frontend addition. S:no cursor/history consumer is needed by #50;
large compatibility surface for a hidden single value. F:future operator UI.
A:possible via backend work, unnecessary here. M:only speculative future expansion
supports its extent. KILL for this delivery; seed is G1's named future frontend need.

### F2 — bounded value plus invalid-line discard
N:explicit invalid record state rather than a post-read length check. S:must prove
partial writes, delimiter loss/absence, editing and no invalid-state recovery.
F:clear native acceptance matrix. A:small byte/state parser with no accumulating
invalid payload. M:bounded protocol parsing and observed OS delivery are independent
of the earlier getpass flag assumption. SURVIVE for native qualification.

### C2 — no editing
N:removes code. S:ordinary typing mistakes would require restarting the attempt;
configured erase/clear support is a small bounded responsibility. F:paste-only
consumer possible. A:implementable but narrows user value unnecessarily if F2 proves
small. M:parsimony supports it, user interaction counters it. REFINE reserve: revive
if basic editing cannot be qualified without a general editor.

### G3 — producer handshake
N:changes producer/reader protocol rather than just consumer. S:current terminal
producer provides no universal handshake; helper exit is not terminal restoration.
F:framed external frontend possible. A:requires named producer/emulator/IPC contract.
M:future-write observation supports the boundary, not the necessity of a new protocol
for ordinary finite lines. DEFERRED until an actual cooperating producer requires it.

### F3 — retire after framed completion or explicit stop
N:invalid input keeps ownership without keeping its content. S:unfinished/endless
input can still wait; remain visibly rejected and Ctrl-C-responsive, never pretend
an arbitrary future producer is controllable. F:truthful terminal/value outcomes.
A:fits existing private owner. M:native future-flush observation plus no-next-action
contract establish its temporal limit independently. SURVIVE for native qualification.

### C3 — immediate overflow exit
N:small fast refusal. S:known remaining paced paste may arrive after echo restoration;
its suffix is not magically removed by prior flush. F:only safe with an external
producer-stop guarantee absent here. A:easy but does not meet owned invalid-line
retirement. M:native flush observation opposes it. KILL for ordinary terminal input;
seed is explicit distinction between rejecting value and ending input lifetime.

### G4 — universal conformance framework
N:larger verification infrastructure. S:unbounded hosts/signals exceed #50; cannot
substitute promises for current evidence. F:shared frontend infrastructure later.
A:not needed to answer bounded host behavior. M:no second consumer/calibration need.
KILL for this delivery; revival requires a named additional support target.

### F4 — native premise first, full composition later
N:targets framing instead of only mode restoration. S:isolated success must not
become product approval. F:replacement plan can carry exact falsifiers. A:local real
PTY/source fixtures available. M:two prior reviews and actual prebuild failure show
why both levels are needed. SURVIVE, including explicit unqualified runtime limits.

### C4 — drop overflow acceptance
N:scope reversal. S:user explicitly asked to survive oversized pastes after this
failure; silently deleting the case does not satisfy the request. F:none for present
goal. A:easy but wrong endpoint. M:no independent support beyond convenience.
KILL; cannot call the old candidate qualified by removing the observed failure.

### Removed size bound
N:removes overflow state. S:retained memory/secrets grow with arbitrary producer;
no onboarding need justifies it. F:unbounded text ingestion is different consumer.
A:possible but wrong domain. M:finite auth values oppose it. KILL, retain finite cap.

## Assembly and axis coverage
First assembly:F1+F2+F3+F4 — byte-observable private input, bounded valid buffer,
invalid-line discard, explicit terminal retirement and staged native/composition
qualification. New interaction: rejecting content does not release the terminal;
drain does not require storing rejected bytes. Critique must prove this combination.
Reserve assembly:C1+existing owner — canonical deadline under a different explicit
user timing policy. Third reserve:G1+private owner — mature backend if complexity or
required contexts justify it. C2 may narrow editing only if a concrete probe demands it.
Axes varied:observation backend, input semantics, retained extent, completion/retirement,
producer cooperation, timing, support breadth and evidence. No single-axis grid.
Artifact grounding:real LoginFlow/private publisher already exist; no “missing auth”
claim. Shared-input convergence challenged by C1/C2/C3/C4 and independent delivery probe.
