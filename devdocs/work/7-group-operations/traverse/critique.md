cover resource authority and false health, including errors during parsing and
storage, not only happy-path Telegram replies. Broadest sensible health meaning
is accurate evidence, not merely callback invocation. No test requires a live
join to determine whether live joins are permitted.

Frame-premise prosecutions, independently of candidate choices:
1. Perhaps access means membership only. If so D1's read probe is unnecessary.
   Counter: the issue says the account can read; SDK metadata and history are
   different requests, and public nonmembership is not a read denial. Preserve
   both observations rather than silently selecting membership as the meaning.
2. Perhaps join count means confirmed successes only. A request followed by a
   lost response then restart makes that number smaller than possible effects.
   Real SDK retry probe records two sends after one helper invocation. Bound
   attempts, explicitly named, while not claiming a global membership ceiling.
3. Perhaps tgdata should return vendor objects. Issue #10's worker boundary and
   actual preview-without-ID/wrapped-results give distinct consumers/states;
   raw truthy objects cannot safely express the issue's ready decision. A small
   portable contract remains justified, without generic worker framework.

transport. Dead: membership=readability, truthy=joined, success-only process
counter, live-only evidence, absent health. Boundary: no-retry join-specific

can work under different explicit consumer/factory requirements. Unexplored:
full approval/payment/webview workflow and multi-host provider; these add
capabilities excluded by the source, so they are not a hidden better #7 solution.

## Phase 3.5 — Assembly A

A = all seven focused candidates, with M9/M10/M11 incorporated.
Prosecution (user perspective): a caller adds a private invite and expects ready;
a preview, a pending request or an empty wrapped acknowledgment can still lack
read proof. If result fields conflate those, the whole assembly fails D1.
Defense: lookup, access and join are separate operations with explicit observation
states. No post-join read is smuggled into the mutation outcome. A caller can
request access separately when ready to spend its read allowance.

Prosecution (failure case): first attempt reaches Telegram, response is lost,
SDK retries, then cancellation occurs. Public-call-only counter loses an attempt;
a success-only refund restores possible effects. Defense: durable sender-seam
claims for both attempts and no uncertainty refund retain the conservative bound.
Quota exhaustion prevents a later send even within the same SDK call.

Prosecution (composition): identity lookup itself could recurse through both
budget guards and metadata could clear prior group denial. Defense: get_me is
not a read/join request family; narrow group-recovery opt-out separates proof
from account transport evidence. Existing read budget still meters access.

Collision: **SURVIVE** on D1–D6, D7 cost is a separate small ledger/guard/value
surface, justified by different resource/proof units. Top-ranked A satisfies the
whole request; component survivors alone do not. No critical caveat requires a
new meaning pass. Runtime verification remains a later gate, not waived here.
