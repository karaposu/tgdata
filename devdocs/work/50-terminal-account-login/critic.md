## Risk R1 — protected controls can be restored too early

**Risk**
The command can turn normal keyboard signals back on while the terminal is still
hidden during cleanup. Pressing the quit key in that interval can terminate the
process before echo is restored. The input routine may pass its normal completion
and Ctrl-C tests while leaving this different control-key history unprotected.

Revision7 step3 says to restore canonical processing with echo disabled, but does
not require preserving the active protected control array/extended/flow flags during
that stage. The source prototype in the bounded-input inquiry builds `settling`
from `original`; VQUIT/VSUSP and IEXTEN/IXON regain their old meanings before the final
write. review-r7/retirement_control_probe.py reproduces actual SIGQUIT delivery in
that hidden original-based stage; constructing it from the protected profile and
changing only ICANON prevents it. The planned private `_terminal_input.py` must fix
this at the owner, not add unrelated command-wide signal interception.

**Severity:** Medium.
**Category:** terminal lifecycle / interruption correctness.
**Impact:** abrupt exit/suspension before terminal restoration; operator terminal
left hidden despite ordinary/first-SIGINT success.
**NoobEng:** the terminal driver interprets keyboard control bytes before Python
reads them. Restoring the original signal bindings has an effect even if no password
value is being read anymore; cleanup still owns a changed terminal at that point.
**Affected areas:** private input intermediate restoration, native matrix and support
contract; no LoginFlow/session/publisher semantics.
