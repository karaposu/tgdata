## Architecture, compatibility and scope assessment

The normalized rows replace embedded member records rather than add another authoritative archive copy. Content digest and metadata validation preserve corruption detection at the member boundary. The public core/wire formats and version stay unchanged; source engines, budgets, health, pool and worker behavior are untouched. There is no new dependency or general storage framework. The example's schema2 and None-return change are deliberate changes to an unmerged example; strict v1 refusal prevents silent reset or false migration.

Read transactions cover view preflight and decoding; write transactions cover current-prior admission and immutable insertion/marker commit. Indexed exact record checks bound confirmation to the original input. The plan explicitly requires avoiding repeated whole-batch decoding and preflighting new-work/view materialization. Native database cache or Python RSS guarantees are not asserted. Integrity tests must preserve the distinction between malformed data and genuinely absent keys.

The alternative of raising allowance or accepting a marker without checking stored data remains rejected. A second post cache, per-batch snapshot archive or shared storage framework would add state without closing a necessary gap here. Later photo trails can consume the stable observed post value; they do not justify changing this contract now.
