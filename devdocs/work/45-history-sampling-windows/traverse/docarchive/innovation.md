## Assembly selected for critique
Use F1+F2+F3+F4 with the tested refinements. Public `TgData.capture_group_history(...)` returns an immutable portable HistoryCapture. A pure `capture.sample(size=300, eligible_ids=None)` returns a separate HistorySample with only selected records plus traceable policy/source/omission metadata. This keeps returned sample content bounded without secretly bundling every captured body into the sample. `HistoryCapture.from_json` supports local replay; the caller owns saving. No convenience source+predicate call is needed initially.

Capture uses UTC intersections of the requested fixed half-open window. Read newest-first within each day, giving unresolved days one page per round. Under a cap too small for every active day, choose evenly spaced day indices; unvisited days remain explicit. Each request fits remaining source-slot capacity (max100) and a fair share among remaining visits in its round. A separate max_requests bounds logical history calls, including empty replies. Successful empty or below-start/full-response evidence ends that day; a short nonempty slice alone does not. Unused capacity from quiet days becomes available to later rounds; no per-day fixed reservation permanently strands it. Unknown rows keep the affected bucket incomplete. Source errors/cancellation preserve accepted capture evidence best effort and propagate unchanged.

Selection operates only on captured ordinary raw messages. Canonical order is publication date then numeric message ID. Allocate up to size equally among nonempty eligible UTC days, redistribute sparse-day spare capacity, and spread remainder days evenly. For k>=2 selections from n ordered candidates, choose indices floor(j*(n-1)/(k-1)); for k1 choose floor((n-1)/2). This includes both extremes for599/300 and handles ties by ID. No randomness/seed is needed. Eligible IDs are explicit existing ordinary captured IDs, with an empty set meaning no candidates and None meaning all; caller predicates run outside the library, so failures leave the capture intact and do not become source failures.

The sample declares raw-message units. Albums retain grouped IDs and selected-album reports name known captured versus selected members; omission cannot silently masquerade as a complete logical post. Global album membership remains unconfirmed. No photo-trail inference runs on sparse samples. Callers needing those existing views can operate on retained capture originals, separately from selecting reading material. There are no batch/cursor/ack fields or progress mutations in either new envelope.

Reuse only the validated raw-page seam: response type/vector, peer/ID/date progression, unknown slots and boundary evidence. Activity and sampling supply their own internal projection. Preserve #44 output and public behavior with parity tests; do not move existing batch/progress engines into a new framework. The raw record serializer/validator may be reused without adopting the MessageBatch envelope.
